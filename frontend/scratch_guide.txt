3. State Management Architecture & Data Separation

A production IoT dashboard demands strict segregation between client state, server cache, real-time telemetry streams, and component-local transient state.

3.1 Four-Tier State Taxonomy

• Global Client State (Zustand): Active 9-tier hierarchy node, time-series scrubber window (8h, 24h, 7d), live telemetry dictionary cache, active KPI filters, alert queue, and modal overlays.

• Server Cache State (TanStack Query): Asset Framework (AF) metadata hierarchy, historical 7-day LPCD rollups, GeoJSON shapefiles, and MIS report datasets.

• Real-Time Event Stream (MQTT.js / WebSocket): Incoming JSON packets from Mosquitto Broker at 14.99.99.166:1889 buffered and dispatched via requestAnimationFrame.

• Component Local State (useState / useReducer): Map viewport zoom/pan coordinates, active measurement drawings, form input drafts, and tooltip hover crosshairs.

6. Enterprise Frontend Directory Structure: Feature-Sliced Domain Architecture

For this frontend application, the recommended structure is an enterprise-grade Feature-Sliced Domain Architecture. This follows the same principle used in large product teams: separate code by business capability first, expose each module through a public API, keep route screens thin, and prevent deep cross-module imports. The structure below is better suited for long-term maintainability than a simple components/pages/hooks layout.

6.1 Enterprise Import Rules and Ownership Boundaries

Use public APIs only: each slice exposes an index.ts file; other modules must not import from internal folders such as ui/, model/, api/, or lib/ directly.

Dependencies flow downward: app can use all layers; pages can use widgets/features/entities/shared; widgets can use features/entities/shared; features can use entities/shared; entities can use shared only.

Pages stay thin: route files compose widgets and pass route parameters, but they should not own API parsing, KPI formulas, or telemetry transformation logic.

Entities own business contracts: API schemas, query keys, mapping functions, validation rules, and domain calculations belong inside entities, not widgets.

Shared stays business-agnostic: shared utilities must not reference JJM-specific concepts such as ESR, LPCD, chlorine, village, or scheme.

Tests live close to ownership: unit tests stay inside the slice they validate; only global mocks, e2e flows, and test helpers belong in tests/.

7. Validation & Testing Standards

Form validation standard: Use Zod as the single source of truth for runtime validation and TypeScript inference. Validation schemas should live with the owning entity or feature, then be reused by React Hook Form, API request/response guards, filter panels, report configuration forms, and MQTT payload normalization where applicable.

Recommended production testing stack: Use Vitest as the primary test runner, React Testing Library for component and integration tests that assert user-visible behavior, MSW for network-level API mocks, and Playwright for the small set of critical end-to-end flows such as login, hierarchy drill-down, telemetry dashboard loading, report export, and GIS map workflows.

Testing ownership rule: Unit tests validate pure utilities, schema refinements, KPI formulas, and state transitions. Component/integration tests validate screen behavior with realistic providers and MSW-backed data. E2E tests should remain focused on high-value production journeys rather than exhaustive click coverage.

7. Step-by-Step Developer Implementation Roadmap

1. Phase 1: Foundations & Token Setup: Install Tailwind CSS, Shadcn UI primitives, and configure theme-tokens.css for Dark/Light theme variable inversion.

2. Phase 2: The 12 Reusable Widgets: Build the 12 core reusable widgets in src/widgets/ matching Section 2 specifications.

3. Phase 3: State & Telemetry Wire-up: Configure the Zustand global store and wire the useMqttTelemetry hook with requestAnimationFrame throttling.

4. Phase 4: Interactive Visualizations & Schematics: Build ScadaHydraulicSchematic SVG component, MaharashtraRegionMap with D3-geo, and telemetry charts with Apache ECharts.

5. Phase 5: Web GIS & MIS Portal Modules: Integrate @arcgis/core (or MapLibre GL) for spatial query and buffer tools; build MIS reporting tables with virtual scrolling and Excel export.
